> 大規模な変更も小さなPRの連鎖に分解。GitHubが提案する新しい開発ワークフローの中心だ。

### これは何か
『GitHub Stacked PRs』は、GitHub CLIの拡張機能で、依存関係のある複数のブランチとプルリクエストを効率的に管理する。複雑な変更を、それぞれが独立した小さなレビュー可能なPRのスタックとして扱えるようになる。

### なぜ私に刺さるか
あなたはDDDやクリーンアーキテクチャを軸に品質確保を重視しており、大規模な変更をどう管理するかは常に課題だろう。Stacked PRsは、変更の粒度を細かくし、各PRのスコープを明確にすることで、レビューの質と開発全体の品質を向上させる。これはあなたの品質重視の思想と完全に一致する。さらに「AI駆動開発」を探求するあなたにとって、AIエージェント統合機能は非常に魅力的だ。AIがStacked PRsの文脈を理解し、コード修正やレビューコメント対応を自律的に行う未来は、まさにあなたが目指す開発者体験の向上に直結する。最近の「力技が通用しなくなった」という自己認識にも、自動化でスマートに乗り越えるための具体的なツールとして響くだろう。

### 活用ユースケース
- 既存のレガシーシステムをDDDやクリーンアーキテクチャの原則でモダナイズする際、ドメイン層、アプリケーション層、インフラ層といった責務ごとの変更を、リスクを抑えながら段階的に導入・レビューする。
- Genkitや自作のAI Agentツール（contextlintなど）の複雑な機能開発において、プロンプト改善、ツール呼び出し追加、UI変更などを小さなPRとして積み重ね、品質を保ちつつ開発スピードを最大化する。
- テックリードとしてチームに小さくレビューしやすいPR文化を導入する際、具体的なツールとして活用。特に若手メンバーに、変更の粒度や責務の分け方を実践的に指導し、コード品質の底上げを図る。

### 最初の一歩
まずは、提供されているウェイティングリストに登録し、アクセス権を得た後、gh extension install で CLI 拡張をインストール。既存のプロジェクトで大規模なリファクタリングを想定し、gh stack init からフローを試してみるべきだ。
